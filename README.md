# 予定帳

個人の家事や引越し準備などを、プロジェクト別のガントチャートで管理するローカル Web アプリです。タスクごとの Todo と、プロジェクト・タスク・Todo に紐づく疑問・懸念を記録できます。

## 起動

Node.js 20.19 以降または 22.12 以降の対応バージョンと npm を用意してください。開発時は Node.js 22.14 を使用しました。

```sh
npm ci
npm run dev
```

ブラウザで [http://localhost:5173/](http://localhost:5173/) を開きます。Windows PowerShell で npm のスクリプト実行が制限されている場合は `npm.cmd` を使います。データの保存先はブラウザプロファイルとオリジンごとの IndexedDB です。同じブラウザで同じ URL を使用してください。ブラウザデータを削除すると登録内容が失われます。

## 操作

1. 左の「プロジェクト」の横にある ＋ でプロジェクトを作成します。
2. 「タスクを追加」または時間軸のダブルクリックで追加します。ダブルクリックした日が開始日と終了日の初期値になります。
3. タスク名またはバーをクリックすると、右の詳細で表題、説明、所属、親、ステータス、進捗、期間を編集できます。「ガントで表示」でタスクの開始日へ移動できます。
4. 子タスクを持たないタスクは、バー全体をドラッグして日程を移動し、バーの左右端をドラッグして開始日・終了日を変えられます。短いバーの編集には日表示が使いやすくなります。
5. 詳細の「子タスク」で子を追加し、一覧の三角ボタンで折りたたみや展開を行います。詳細の上下ボタンで、プロジェクトと親が同じタスク同士の順序を変更できます。
6. 左のナビゲーションで全件とプロジェクト別表示を切り替えられます。上部の日／週／月で目盛りを切り替え、期間ボタンや時間軸の横ドラッグで移動できます。
7. 保存済みタスクの詳細で「Todo」を選ぶと、項目の追加・チェック・削除ができます。変更は自動で保存され、完了件数と割合に反映されます。
8. プロジェクトを選んだ画面上部、タスク詳細の「疑問・懸念」、または各 Todo の吹き出しボタンから登録します。画面の「新規登録先」で紐づけ先を確認できます。プロジェクトの一覧には配下のタスク・Todo の項目も紐づけ先つきで表示されます。
9. 未解消の項目があると、プロジェクト名、ガントのタスク行、該当 Todo に件数が表示されます。ガントの件数をクリックすると、子タスク・Todo を含む関連一覧が開きます。解消したら一覧で項目を開き、「解消済みにする」にチェックして解消内容を保存します。
10. ガント上部の「表示設定」で、プロジェクト行と Todo 行を個別に切り替えられます。両方を有効にすると、プロジェクト → 親・子タスク → 各タスクの Todo を一つのガントで確認できます。設定はブラウザに保存されます。
11. Todo のバーをクリックするか、タスク詳細の Todo にあるカレンダーボタンを押すと日程を設定できます。バーのドラッグや両端の伸縮でも変更できます。「タスクの日程に戻す」で所属タスクの期間を再び使います。

ガントでは、プロジェクトは四角い二重枠、親タスクは両端に短い脚があるバー、Todo は細いカプセル形で表示します。左の行名にも対応する目印があります。

## Phase 1 の設計

### 技術検証

vis-timeline を採用しました。公式 API の確認後、React の開発ビルドと Edge で操作を検証しました。

| 確認項目 | 採用した方法 |
| --- | --- |
| 親子階層 | ライブラリの `nestedGroups` で入れ子を表現できます。アプリではタスクの木構造から表示順と階層を求め、展開中の行をフラットなグループとして渡します。行ラベルにインデントを付け、期間・進捗の集約は画面の折りたたみ状態から独立させています。 |
| 移動・伸縮 | 範囲アイテムの時刻編集と `onMove` を使います。変更を日付に変換して保存し、IndexedDB の購読結果でチャートに反映します。 |
| 詳細の表示 | 左の行ラベルをボタンとして描画し、バーは Timeline のクリックイベントで右ドロワーを開きます。 |
| 日／週／月 | `timeAxis.scale` と `setWindow` を組み合わせ、約14日／8週／6か月を表示します。 |
| React | DOM の管理を専用コンポーネントに閉じ、マウント後に Timeline を生成し、アンマウントで破棄します。データ更新時は vis-data の DataSet へ差分を反映します。React Strict Mode を有効にした開発環境で動作を確認しました。 |
| ライセンス | vis-timeline は MIT または Apache-2.0 のデュアルライセンスです。MIT を選択でき、商用利用が可能です。再配布時は選択したライセンスの条件が適用されます。 |

日付軸、ドラッグ判定、伸縮を vis-timeline でカバーできるため、独自実装で必要になる時刻座標やポインター操作の管理を省けます。親子集約と行の操作は将来ガントライブラリを交換しても再利用できます。

[vis-timeline 公式 API](https://visjs.github.io/vis-timeline/docs/timeline/) · [公式編集デモ](https://visjs.github.io/vis-timeline/examples/timeline/editing/editingItemsCallbacks.html) · [公式 MIT ライセンス](https://github.com/visjs/vis-timeline/blob/master/LICENSE.MIT.txt)

### 仕様上の判断と技術課題

| 項目 | Phase 1 の判断 |
| --- | --- |
| 日付の境界 | 予定日はブラウザの現地暦で `YYYY-MM-DD`、記録日時は UTC の ISO 8601 文字列です。初期値は同日です。画面の終了日は含み、ガントへは終了日の翌日午前0時を渡します。 |
| 親の期間と進捗 | 子が一件でもあれば、実効期間を子の最小開始日から最大終了日までとします。進捗は直接の子の実効進捗の平均を階層ごとに整数に丸めます。親の手入力値は保存しておき、子がいなくなった時に再び表示します。 |
| Todo と進捗 | 子のないタスクに Todo があれば、完了数を項目数で割った割合を整数に丸め、ガントに表示します。Todo をすべて削除すると従来の手入力値に戻ります。子のあるタスクでは、自身の Todo の完了割合を「Todo」内に表示し、ガントの進捗は子タスクから集約します。 |
| プロジェクトのガント | プロジェクトのバーは配下のタスクの最も早い開始日から最も遅い終了日までです。進捗は直下のタスクの実効進捗の平均です。配下のタスクを折りたためます。タスクがなければプロジェクト行だけが表示されます。 |
| Todo のガント | 日付を指定していない Todo は所属タスクの期間に連動し、ガントでは破線で表示します。指定した日程は Todo に保存します。タスクとプロジェクトの期間は従来どおりタスクの日付で決まります。 |
| ステータス | 進捗とは独立して手動設定します。親のステータスも手動です。 |
| 親の変更とプロジェクト間移動 | 同じプロジェクトのタスクのみ親にできます。自分と子孫は候補から除外し、保存時にも検証します。子を持つタスクのプロジェクト間移動は、子孫の扱いが未指定のため制限します。 |
| 並び順とインデント | 並び順は同じプロジェクト・同じ親の範囲で変更します。深い階層も扱い、行ラベルの幅を確保するため視覚上の字下げには上限があります。 |
| 未解消件数 | Todo の未解消件数は所属タスク・祖先タスク・プロジェクトにも反映します。タスクの疑問・懸念はそのタスクと上位に、プロジェクト直下の疑問・懸念はプロジェクトに表示します。区別は件数と登録先で行い、完了や編集は手動で操作できます。 |
| 削除 | タスクを削除すると、確認後に子孫と関連 Todo・コメント・疑問・懸念を単一のトランザクションで削除します。疑問・懸念が付いた Todo を単独で削除する際も確認します。 |
| 画面の負荷 | ガントが表示行の DOM を持つため、大量タスクでの描画性能は追加検証が必要です。本番ビルドでは vis-timeline を含む JavaScript が約1 MB で、Vite のチャンクサイズ警告が出ます。 |
| 後続機能の判断 | 今週の区切りと期限集計で完了を含めるかは Phase 3、置換バックアップの検証と将来の形式移行は Phase 4 で定義します。 |

### データモデル

全エンティティが `id`、`createdAt`、`updatedAt` を持ちます。作成時に UUID を割り当てます。

| エンティティ | 追加フィールド | 関係 |
| --- | --- | --- |
| Project | `name`, `description` | 複数のタスクを持つ |
| Task | `projectId`, `parentTaskId`, `title`, `description`, `startDate`, `endDate`, `status`, `progress`, `sortOrder` | 1プロジェクトに所属し、同じプロジェクトの親を任意で持つ |
| Todo | `taskId`, `title`, `completed`, 任意の `schedule` | 1タスクに所属する。既存の Todo は所属タスクの日程を使用する |
| Comment | `taskId`, `body` | 1タスクに所属する。Phase 2 で操作を追加 |
| Issue | `targetType`, `targetId`, `commentId`, `type`, `title`, `description`, `status`, `resolution`, `resolvedAt` | プロジェクト・タスク・Todo のいずれか1件を参照する。既存データの `taskId` はタスクへの参照として引き継ぐ |

### ディレクトリとコンポーネント

```text
src/
  App.tsx                  左ナビゲーション、選択とフィルター、画面操作
  components/
    Gantt.tsx              vis-timeline のライフサイクル、行とバー、操作イベント
    GanttSettingsDialog.tsx  プロジェクト行と Todo 行の表示設定
    TaskDrawer.tsx         タスクの詳細・編集・子追加・並べ替え
    TaskTodos.tsx          Todo の追加・チェック・削除
    IssueList.tsx          疑問・懸念の一覧・登録先・詳細・解消記録
    ProjectDialog.tsx      プロジェクト作成フォーム
    ui/dialog.tsx          shadcn/ui の構成に沿った Radix Dialog
  domain/
    model.ts               エンティティの型
    dates.ts               保存日付とガントの期間の相互変換
    gantt.ts               表示設定に応じた階層行とプロジェクト期間の集約
    issues.ts              登録先と未解消件数の集約
    tasks.ts               階層、集約、入力検証
  data/
    ganttSettings.ts       ブラウザごとのガント表示設定
    repository.ts          Dexie のテーブル、購読、書き込みトランザクション
tests/                     ドメイン、IndexedDB、Edge のシナリオ検証
```

UI はリポジトリの購読と操作を呼び出し、Dexie のテーブルに直接アクセスしません。別の保存先を採用する場合は、リポジトリの実装を差し替える構成です。

### Phase 1 の実装順序と確認

1. Vite／React の起動確認と vis-timeline API の適合性を調査。
2. 日付処理、親子構造、Dexie スキーマを用意し、作成・更新・削除の整合性をテスト。
3. プロジェクトの作成と切り替え、ドロワー、階層ガントを接続。
4. 時間軸からの作成、バー移動・両端の伸縮、並べ替え、保存の反映を接続。
5. 型チェック、本番ビルド、自動テスト、ブラウザでの操作と再読み込みを確認。

```sh
npm test
npm run build
```

Microsoft Edge がインストールされた環境では、開発サーバーを起動したまま別の端末で `npm run test:browser` を実行できます。テストは一時ブラウザプロファイルを使用します。必要に応じて環境変数 `TEST_BROWSER_CHANNEL` と `TEST_APP_URL` でブラウザと URL を指定できます。

## 残りの Phase

- **Phase 2** の残りは、作業履歴の追加・編集と、疑問・懸念をコメントから登録・参照する画面です。
- **Phase 3** でタスク件数、今週の期限、期限超過、プロジェクト進捗、未解決事項の集計と、カードからガントへの絞り込みを追加します。
- **Phase 4** で形式バージョン付き JSON の入出力、確認付きの全置換、形式・参照の検証とロールバック、入力・エラー表示の仕上げを行います。
